# Ingredient icon stored as a literal react-icons component name

Meat Type and Side Type values (`IngredientTagValue`) now carry an `icon` field so the Quiz and Meal cards can show a picture per ingredient instead of the old 4-entry hardcoded emoji map. The `icon` value is the literal name of a `react-icons/gi` (Game Icons) component, e.g. `"GiPig"` for pork — stored as-is in the catalog seed data (`backend/src/meal/domain/catalog/data.ts`) and in Mongo, and resolved to a component on the frontend with a one-line `Icons[iconKey]` lookup. We considered storing a neutral semantic key (e.g. `"pig"`) and mapping it to a `react-icons` component via a frontend registry instead, which would keep the backend domain free of any frontend-library naming. We chose the direct approach because it avoids maintaining a second ~80-entry mapping table that would just duplicate the data already curated in `data.ts`, at the cost of coupling the domain data to `react-icons`' naming — swapping icon libraries later means migrating every catalog entry, not just a frontend registry.
